# Life Manager iPhone App 实施计划

> 状态：Draft<br>
> 目标版本：iPhone 本地版 v1<br>
> 更新时间：2026-08-27<br>
> 配套规格：[spec.md](spec.md)

## 1. 目标

在不重写现有 9 个业务模块的前提下，将 Life Manager 制作为可安装到个人 iPhone 的轻原生 App。第一版保留 Web 界面和业务逻辑，由 SwiftUI 提供应用外壳，并补齐离线资源、可靠持久化、Face ID、文件备份、系统通知和原生触感。

第一版完成后应满足：

- 可通过 Xcode 安装到个人 iPhone。
- 飞行模式下可以使用全部核心记录功能、图片、字体、图标和图表。
- 强制退出或覆盖安装后数据仍能恢复。
- 可以通过 Files/iCloud Drive 手动导出和导入 JSON 备份。
- 定时计划、目标截止和单词复习可以生成本地通知。
- 启动和回到前台时可以使用 Face ID 或设备密码解锁。

## 2. 实施原则

- 先封装、再增强，不在 v1 同时进行全量 SwiftUI 重写。
- Web 业务状态只有一个事实来源，不在 JavaScript 和 Swift 中维护两套业务模型。
- `localStorage` 用于页面运行，Application Support 中的原子 JSON 文件用于可靠恢复。
- 所有运行资源随 App 打包，不依赖 CDN。
- 当前未提交的 `index.html` 修改属于现有工作，结构调整时必须完整保留。
- 文件必须遵守 [spec.md 的目标目录结构](spec.md#6-目标目录结构)，不得在仓库根目录新增临时实现文件。

## 3. 阶段计划

### 阶段 0：建立结构基线

- [ ] 保存当前工作树状态和功能基线，不覆盖未提交修改。
- [ ] 将正式 Web 源码迁入 `web/`，包含 `index.html` 和 `assets/`。
- [ ] 将第三方前端资源放入 `web/vendor/`，并记录来源、版本和许可证。
- [ ] 将正式 iOS 工程放入 `apps/ios/`。
- [ ] 正式 App 提供 Canvas/模拟器预览后，移除独立的 `ios-preview/` 包，避免两套预览入口。
- [ ] 更新根 README 的运行命令和目录说明。

完成门槛：结构调整前后，浏览器版功能、样式和现有本地数据 schema 均不变化。

### 阶段 1：创建可离线运行的 iOS 外壳

- [ ] 创建 SwiftUI iOS App，最低系统版本 iOS 17。
- [ ] 创建 `WKWebView` 容器并从 App Bundle 加载 `web/` 资源。
- [ ] 使用持久化 `WKWebsiteDataStore.default()`，禁止非必要外部导航。
- [ ] 本地化 Chart.js、Phosphor Icons 和 Noto Serif SC，移除 Google Fonts、unpkg 和 jsDelivr 请求。
- [ ] 添加启动页、AppIcon、暖纸背景和安全区处理。

完成门槛：断网启动后九个模块均可打开，图片、图标、字体和图表正常显示，控制台无资源错误。

### 阶段 2：实现原生桥接和可靠存储

- [ ] 实现单一 `lifeManager` JavaScript message handler。
- [ ] Web 每次成功 `saveState()` 后发送规范化状态。
- [ ] 原生层原子写入 `Application Support/LifeManager/state.json`，写入前保留可恢复的上一版本。
- [ ] App 启动时读取原生状态，并在页面脚本执行前注入 `localStorage`。
- [ ] 对无法解析、版本过高或校验失败的数据执行安全回退，不覆盖最后一份有效数据。
- [ ] 实现原生文件导入、导出与导入前备份。

完成门槛：新增记录后强制退出并重启可恢复；损坏备份不会覆盖有效状态；现有 schema v1–v3 备份可以导入。

### 阶段 3：实现隐私和原生体验

- [ ] 启动及从后台恢复时使用 LocalAuthentication 解锁。
- [ ] 优先 Face ID，失败后允许使用设备密码；不支持认证的设备直接进入。
- [ ] 将关键成功、警告和轻触反馈接入原生 haptic。
- [ ] 保留 Web 端触感作为非 iOS 环境的降级路径，避免重复触发。

完成门槛：真机上可以正常解锁；认证取消时不显示生活数据；模拟器和无 Face ID 设备仍可使用。

### 阶段 4：实现关键本地通知

- [ ] Web 根据当前状态生成统一通知描述数组。
- [ ] 原生层请求通知权限，并按通知 ID 增量更新未来 30 天提醒。
- [ ] 为有开始时间且未完成的计划创建开始时间提醒。
- [ ] 为未完成目标创建截止日前一天 20:00 提醒。
- [ ] 按日期聚合待复习单词，并在当天 20:00 提醒一次。
- [ ] 完成、删除、延期或归档后取消对应旧通知。
- [ ] 权限被拒绝时保持其他功能可用并提供非阻塞提示。

完成门槛：真机可以验证通知的创建、修改、取消和聚合；同一业务对象不会产生重复通知。

### 阶段 5：回归、真机安装和交付

- [ ] 运行 JavaScript 语法检查、备份迁移测试和 Swift 单元测试。
- [ ] 在 360px、402px 以及 iPhone 17 Pro 模拟器回归九个模块。
- [ ] 验证键盘、安全区、底栏、详情导航、滚动和横向溢出。
- [ ] 验证飞行模式、强制退出、覆盖安装、导出、导入和故障恢复。
- [ ] 使用 Xcode Personal Team 安装到个人 iPhone。
- [ ] 在 README 中记录安装、重新签名、备份恢复和故障排查步骤。

完成门槛：满足 spec 中全部 P0 验收标准，且不引入阻塞性回归。

## 4. 测试矩阵

| 范围 | 场景 | 预期结果 |
| --- | --- | --- |
| 离线 | 首次安装后开启飞行模式 | 九个模块与全部静态资源正常 |
| 持久化 | 新增记录、强制退出、重启 | 数据完整恢复且无重复 |
| 迁移 | 导入 schema v1、v2、v3 | 规范化为当前 schema |
| 失败恢复 | 注入损坏 JSON 或中断写入 | 继续使用最后有效状态 |
| 通知 | 新建、修改、完成、删除计划 | 通知同步创建、调整或取消 |
| 隐私 | 启动、后台恢复、取消认证 | 未认证前不展示私人内容 |
| 视觉 | 360px、402px、iPhone 17 Pro | 无横向溢出，安全区正确 |
| 备份 | 导出、卸载、重装、导入 | 手动备份可完整恢复 |

## 5. 明确不在 v1 实现

- Android、iPad 专属布局、macOS 或 Web 公网部署。
- App Store 上架、TestFlight 和付费功能。
- 账号系统、服务器、CloudKit 自动同步和多人协作。
- 全量 SwiftUI 重写、Widget、Apple Watch、HealthKit。
- 联网大模型；“AI 深度点评”继续使用现有本地规则。

## 6. 交付物

- `apps/ios/` 下可构建、可安装的正式工程。
- `web/` 下可独立运行且完全离线的 Web 应用。
- 原生桥接、持久化、认证和通知测试。
- 更新后的 README、CHANGELOG 和本目录文档。
- 一份可在 Files/iCloud Drive 中保存并重新导入的示例备份。
